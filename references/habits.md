# 本地 Git 整理与 GitHub 上传 · 习惯与注意事项

每踩一次坑就往这里追加一条，写清「什么情况、怎么错、正确做法」。下面是初稿，用着用着按实际情况改。

## 红线

- 每趟先取舍：用不到的技能不读、不写进本次记录，也不为了「走全流程」硬凑步骤；动手前用一句话说明这次用了哪些、哪些不用、为什么。
- 远端操作走 GitHub 网站（本机没有 `gh`，也没有图形客户端）。需要点按钮的步骤用浏览器带着用户一起点，不要只给文字步骤让他自己找。
- 凭据不进版本库：token、密码、`.env`、私钥、服务器地址列表。发现疑似文件先排除再提交，不抱侥幸。
- 凭据值也不写进这份工作流、不写进对话和日志；需要时只写「见哪个文件」。
- 同一个远端只留一个正本仓库，第二个副本要么归档、要么明确标成只读备份。
- 破坏性动作先问：强推、覆盖远端历史、删远端分支或标签、改仓库可见性、加协作者。
- 推完必须真验：重新看一次远端的分支和最新提交，`git push` 没报错不等于远端就是想要的样子。

## 踩过的坑

- `D:\AI\NewApi管理_repo` 看着像重复仓库，其实是主仓库的 worktree，推档案仓就靠它。判断重复前先看 `.git` 是文件还是目录、再跑 `git worktree list`，别按目录名猜。
- 本地 `main` 比远端多提交不一定是漏推。这套仓库的档案仓只收脱敏精选的改动，两端本来就不会一样。
